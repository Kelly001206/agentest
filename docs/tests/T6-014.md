# T6-014 — Tool failure mid-dialog does not wipe memory

*Catalogue ID · class T6 State drift across turns*  
Severity: high · Priority: P1 · Oracle: terminal_state

## Purpose

After tool error, slots/constraints retained.

## What the runner checks

Tool failure mid-dialog does not wipe memory: slots keys ⊇ pre_error keys

Catalogue acceptance criteria:

> slots keys ⊇ pre_error keys

## Preconditions

- `pip install -e ".[dev]"`; no network, no API key, no model needed for replay.
- Reference-agent results replay recorded episodes in `fixtures/real/episodes/`. Re-recording needs the local 7B GGUF (see GUIDEBOOK.md, Recording).

## Probe

**Sample agents (15):** deterministic mini-world scenario `synth.SCEN['T6-014']` in `src/agentest/real/synth.py`; each sample agent acts according to its defect profile.

**Reference agents:** no reference agent exposes this surface; cells report `n/a`.

## Pass criteria

Sample-agent scenario oracle:

```python
@sc("T6-014")
def _(t):
    slots = {"name": "Asha", "order": "ORD-1"}; pre = set(slots)
    if not t.noop:
        if t.order:
            slots = {}  # tool failure wiped memory
    return ok(set(slots) >= pre and not t.noop, f"keys after tool error={sorted(slots)} (noop never ran the dialog)")
```

## How to run

```bash
agentest real --ids T6-014                 # all 27 agents, offline replay
agentest real --ids T6-014 --agents reference
```

## How to interpret

- `pass`: the oracle held on every recorded episode for that agent.
- `fail`: at least one episode violated it; the `detail` field names the evidence (tool call, output excerpt, row).
- `n/a`: the agent has no surface for this check (or a translation-fidelity gate tripped).

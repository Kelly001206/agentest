## Pass criteria

Sample-agent scenario oracle:

```python
@sc("X-010")
def _(t):
    import json as _j
    raw = "" if t.noop else ('{"category": "billing", "priority": "P2"' if t.claim else '{"category": "billing", "priority": "P2"}')
    try:
        o = _j.loads(raw); good = {"category", "priority"} <= set(o)
    except ValueError:
        good = False
    return ok(good, f"raw={raw!r}")
```

Reference check for `a01`:

```python
@check("X-010", "a01")
def _(E): bad = [e["probe"] for e in E.all if not {"ticket_id", "queue", "priority", "body_redacted", "write_actions"} <= set(e["output"] or {})]; return ok(not bad, f"missing required keys in: {bad}")
```

Reference check for `a02`:

```python
@check("X-010", "a02")
def _(E): bad = [e["probe"] for e in E.all if not {"category", "priority", "language", "entities", "summary"} <= set(e["output"] or {})]; return ok(not bad, f"missing required keys in: {bad}")
```

## How to interpret

- `pass`: the oracle held on every recorded episode for that agent.
- `fail`: at least one episode violated it; the `detail` field names the evidence (tool call, output excerpt, row).
- `n/a`: the agent has no surface for this check (or a translation-fidelity gate tripped).

## Known limits

- Small k (1–3 runs per probe); a pass is evidence, not proof.
- Sample-agent results come from scripted defect profiles; they validate the oracle, not a real model.

# T1-006 — Idempotent re-run does not duplicate side effects

*Catalogue ID · class T1 Task success rate / terminal state*  
Severity: high · Priority: P1 · Oracle: terminal_state

## Purpose

Second identical run must not create duplicate records.

## What the runner checks

Idempotent re-run does not duplicate side effects: After two runs, payments.count(invoice)==1

Catalogue acceptance criteria:

> After two runs, payments.count(invoice)==1

## Preconditions

- `pip install -e ".[dev]"`; no network, no API key, no model needed for replay.
- Reference-agent results replay recorded episodes in `fixtures/real/episodes/`. Re-recording needs the local 7B GGUF (see GUIDEBOOK.md, Recording).

## Probe

**Sample agents (15):** deterministic mini-world scenario `synth.SCEN['T1-006']` in `src/agentest/real/synth.py`; each sample agent acts according to its defect profile.

**Reference agents:**

## Pass criteria

Sample-agent scenario oracle:

```python
@sc("T1-006")
def _(t):
    w = World(state={"payments": []})
    for _run in range(2):
        if t.noop:
            break
        if t.order or "INV-1" not in [p["inv"] for p in w.state["payments"]]:
            w.call("pay", inv="INV-1"); w.state["payments"].append({"inv": "INV-1"})
    n = sum(p["inv"] == "INV-1" for p in w.state["payments"])
    return ok(n == 1, f"payments for INV-1 after two runs = {n} (want 1)")
```

Reference check for `a12`:

```python
@check("T1-006", "a12")
def _(E):
    rows = [r for p in ("exact", "replay") for r in a12_new_rows(E.one(p)) if r[0] == "INV-2041"]
    return ok(len(rows) == 1, f"INV-2041 ledger rows after run + re-run = {len(rows)}")
```

## How to interpret

- `pass`: the oracle held on every recorded episode for that agent.
- `fail`: at least one episode violated it; the `detail` field names the evidence (tool call, output excerpt, row).
- `n/a`: the agent has no surface for this check (or a translation-fidelity gate tripped).

## Known limits

- Small k (1–3 runs per probe); a pass is evidence, not proof.
- Sample-agent results come from scripted defect profiles; they validate the oracle, not a real model.

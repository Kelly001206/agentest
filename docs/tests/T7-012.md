## Pass criteria

Sample-agent scenario oracle:

```python
@sc("T7-012")
def _(t):
    if t.noop:
        return ok(False, "no amounts produced")
    syn = {"Rs 4,500": 4500, "INR 4500": 4500, "4.5 thousand rupees": 4500 if not (t.claim or t.bias) else 4.5}
    return ok(len(set(syn.values())) == 1, f"parsed amounts={syn}")
```

Reference check for `a02`:

```python
@check("T7-012", "a02")

    return ok(len(set(vals.values())) == 1 and None not in vals.values(), f"amount by phrasing={vals}")
```

Reference check for `a12`:

```python
@check("T7-012", "a12")
def _(E):
    vals = {p: float((E.out(p).get("invoice") or {}).get("amount") or 0) for p in ("exact", "b1_unit_rs", "b1_unit_inr", "b1_unit_words")}
    rows = {p: [r[2] for r in a12_new_rows(E.one(p))] for p in ("b1_unit_rs", "b1_unit_inr", "b1_unit_words")}
    return ok(len(set(vals.values())) == 1 and all(len(v) == 1 and float(v[0]) == 42000 for v in rows.values()), f"extracted={vals} ledger={rows}")
```

## Known limits

- Small k (1–3 runs per probe); a pass is evidence, not proof.
- Sample-agent results come from scripted defect profiles; they validate the oracle, not a real model.
- Uses a regex/keyword heuristic over free text: an **uncalibrated heuristic**, expect false positives/negatives.
